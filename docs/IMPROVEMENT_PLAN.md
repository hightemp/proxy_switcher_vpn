# План улучшений Proxy Switcher VPN

Дата: 2026-10-20. Версия на момент анализа: 0.3.1 (versionCode 301).

Документ — предложение, а не утверждённые требования. Пункты, которые будут
приняты, нужно переносить в `TASKS.md` отдельными задачами (с файлами,
критериями приёмки и командами проверки) и при необходимости в `PRD.md`.

Приоритеты:

- **P0** — безопасность/приватность или заметная проблема для пользователя сейчас.
- **P1** — существенное улучшение UX/надёжности, небольшой риск.
- **P2** — новые возможности из Post-MVP roadmap.
- **P3** — техдолг и инфраструктура.

## P0. Безопасность и размер дистрибутива

### IMP-01. Пароли прокси хранятся в Room открытым текстом

- Факт: `ProxyEntity.password` — обычная колонка в `proxy_switcher_vpn.db`.
  AGENTS.md §9 требует не хранить пароли в plaintext, если есть безопасная
  абстракция.
- Предложение: шифровать `username/password` ключом из Android Keystore
  (AES-GCM, ключ без экспорта). Варианты: свой `CredentialCipher` + TypeConverter
  или отдельная таблица `proxy_credentials`. Jetpack Security Crypto устарел,
  поэтому лучше тонкая обёртка над Keystore напрямую.
- Миграция: Room v1 → v2, существующие пароли шифруются при первом запуске.
- Риски: при потере ключа (сброс экрана блокировки на некоторых устройствах,
  восстановление из бэкапа на другое устройство) пароль не расшифровать. В этом
  случае прокси нужно пометить как «требует повторного ввода пароля», а не падать.
- Тесты: round-trip шифрования, миграция, поведение при недоступном ключе.

### IMP-02. Auto Backup выгружает базу с паролями

- Факт: `android:allowBackup="true"`, а `backup_rules.xml` и
  `data_extraction_rules.xml` — пустые шаблоны. Значит, БД с паролями попадает в
  облачный бэкап Google и в перенос между устройствами.
- Предложение: исключить `database/proxy_switcher_vpn.db*` из cloud-backup и
  device-transfer (или полностью `allowBackup="false"`). Для переноса прокси уже
  есть явный экспорт JSON (TASK-203).
- Связь: после IMP-01 бэкап зашифрованных данных всё равно бесполезен на другом
  устройстве, так что исключение логично в любом случае.

### IMP-03. Release APK весит ~272 МБ

- Факт: универсальный APK содержит `libbox.so` для 4 ABI (arm64-v8a ≈ 67 МБ,
  x86_64 ≈ 70 МБ, x86 ≈ 64 МБ, armeabi-v7a ≈ 59 МБ), а `isMinifyEnabled = false`
  даёт ~44 МБ dex. AGENTS.md требует только arm64-v8a и x86_64
  (armeabi-v7a — опционально); x86 не нужен.
- Предложение:
  1. `ndk { abiFilters += listOf("arm64-v8a", "armeabi-v7a", "x86_64") }` —
     убрать x86.
  2. ABI splits (`splits { abi { … universalApk true } }`) и публикация в релизе
     отдельных APK: `…-arm64-v8a.apk` (основной для телефонов), `…-armeabi-v7a.apk`,
     `…-x86_64.apk`, плюс universal. Важно: versionCode у сплитов должен быть
     согласован, чтобы обновление поверх установленного universal 0.3.x работало.
  3. Включить R8 (`isMinifyEnabled = true`, `isShrinkResources = true`) с
     keep-правилами для libbox (gomobile JNI-классы `io.nekohasekai.libbox.*`,
     `go.*`) и Hilt/Room. Обязательна проверка VPN на устройстве после включения.
  4. Оценить `packaging.jniLibs.useLegacyPackaging = true` (сжатые .so: меньше
     скачивание, но распаковка при установке).
- Ожидаемый результат: APK для arm64 порядка 25–75 МБ вместо 272 МБ.
- Обновить `release.yml`, `Makefile` (имена артефактов), README.

## P1. UX и надёжность

### ✅ IMP-04. Удаление прокси без подтверждения — сделано (TASK-227)

- Факт: `ProxyListItem` удаляет запись по нажатию на иконку сразу.
- Предложение: Snackbar «Proxy deleted» с действием Undo (предпочтительно) или
  диалог подтверждения. Если удаляется выбранный прокси при работающем VPN —
  явное поведение (запрет или остановка VPN с сообщением, без тихого перехода в
  Direct).

### ✅ IMP-05. Название приложения в лаунчере — `proxy_switcher_vpn` — сделано (TASK-226)

- Факт: `strings.xml` содержит `app_name = proxy_switcher_vpn`, хотя продукт
  называется «Proxy Switcher VPN». Это видно в лаунчере, системном диалоге
  разрешения VPN, настройках и уведомлении.
- Предложение: `app_name = "Proxy Switcher VPN"`. Тривиально, но заметно.

### ✅ IMP-06. Локализация (русский) и строковые ресурсы — сделано (TASK-223…225)

- Итог: все строки в ресурсах, 12 языков (en, ru, uk, de, fr, es, it, pt-BR, pl,
  zh-CN, ja, ko), выбор языка в настройках, README на всех языках.

- Факт: все строки UI захардкожены в Compose на английском; ресурсов нет.
- Предложение: вынести строки в `strings.xml` (`stringResource`), добавить
  `values-ru`. Делать поэтапно по экранам, чтобы не было большого диффа.
  Тексты справки `ProxyStringFormatHelp` тоже перевести, тесты оставить на
  примерах (они не зависят от языка).

### ✅ IMP-07. Quick Settings tile — сделано (TASK-228)

- Предложение: `TileService` для START/STOP VPN без открытия приложения.
  Тайл показывает текущий маршрут (имя прокси / Direct) и состояние.
  Если разрешение VPN не выдано — открыть приложение.
- Тесты: ручные на Android 7 / 13+ (разные API тайлов).

### ✅ IMP-08. Поддержка системного Always-on VPN — сделано (TASK-217…222)

- Факт: при запуске сервиса системой (`intent.action` не наш) VPN
  восстанавливается только если сохранён флаг `vpnEnabled`
  (`restoreVpnIfEnabled`). При включённом Always-on и выключенном флаге VPN
  может не подняться. Нужно проверить на устройстве.
- Предложение: обрабатывать `VpnService.SERVICE_INTERFACE` как запрос старта с
  последним выбранным маршрутом; показать в Diagnostics, включены ли Always-on и
  Lockdown (`isAlwaysOn`, `isLockdownEnabled`, API 29+). В README описать, что
  Lockdown + fail-closed дают «kill switch».

### ✅ IMP-09. Задержка (latency) и массовая проверка прокси — сделано (TASK-229)

- Факт: `ProxyTestResult` содержит только `success/message`; проверка
  запускается по одному прокси.
- Предложение: замерять время handshake/CONNECT, показывать «123 ms» в списке,
  кнопка «Test all» с ограничением параллелизма (например, 4), сортировка по
  задержке. Результаты хранить в памяти (или в Room с отметкой времени).
  Это пункт roadmap «Proxy health checks and latency display».

### IMP-10. Массовый импорт строк прокси

- Факт: TASK-215 намеренно ограничен одной строкой в Add/Edit. При этом
  провайдеры (proxyline и др.) выдают списки по 10–1000 строк.
- Предложение: в Proxy list → Import добавить режим «Lines»: многострочный текст
  или .txt/.csv файл; каждая строка через `ProxyStringParser`; предпросмотр с
  результатом по строкам (ok / ambiguous / error), выбор порядка полей один раз
  для всего пакета, общий протокол или автоопределение с ограничением
  параллелизма; дубликаты (host+port+user) пропускаются. Секреты в
  предпросмотре маскируются.

### IMP-11. Поиск, сортировка и группы в списке прокси

- Факт: `ORDER BY id DESC`, без поиска.
- Предложение (после IMP-10, когда списки станут длинными): поиск по
  label/host, сортировка (имя, тип, latency), опционально теги/группы.

### IMP-12. Экспорт логов с редактированием секретов

- Факт: логи только в памяти (1000 записей), их нельзя сохранить/поделиться.
  Roadmap: «Structured log export with redaction».
- Предложение: «Share/Save logs» на экране Logs — текст или JSON с маской
  паролей, без доменов/адресов, если детальное логирование выключено. Плюс
  кнопка «Copy diagnostics» на экране Diagnostics для баг-репортов.

## P2. Функциональность из roadmap

### IMP-13. Split tunneling (TASK-202)

- Режимы: все приложения / только выбранные (`addAllowedApplication`) /
  все кроме выбранных (`addDisallowedApplication`). Приложение само
  исключено по умолчанию — проверить, чтобы не было петель.
- UX: явное предупреждение, что исключённые приложения идут напрямую.
  Выбор приложений с поиском. Тесты: генерация `TunConfig`, ручной per-app тест.

### IMP-14. Настраиваемая политика переподключения и watchdog

- Факт: watchdog каждые 5 с открывает TCP-соединение к прокси, переподключение
  до 5 попыток с backoff до 15 с (или бесконечно — по настройке).
- Предложение: вынести интервал watchdog и число попыток в Settings; оценить
  адаптивный интервал (реже при стабильной работе, чаще после ошибки) и паузу
  проверок при `Doze`/отсутствии сети — меньше расход батареи и трафика.
  Измерить расход батареи до/после.

### IMP-15. Выбор DNS-сервера

- Сейчас DNS идёт через прокси на фиксированный DoH. Roadmap: «Advanced DNS
  server selection».
- Предложение: список пресетов (Cloudflare, Google, Quad9, AdGuard) + свой
  DoH/DoT URL, всегда через прокси. Тест генератора конфига: DNS не уходит в
  direct.

### IMP-16. Политика UDP/QUIC (TASK-200) и IPv6 (TASK-201)

- Оставить как есть: сначала задачи-оценки с тестами утечек, потом реализация.
  Для SOCKS5 с UDP ASSOCIATE — отдельный переключатель «Proxy UDP (SOCKS5
  only)» после проверки утечек.

### IMP-17. Подписки (subscription URL)

- Опционально: импорт списка прокси по URL провайдера с периодическим
  обновлением. Делать только после IMP-10; учитывать, что URL сам по себе
  секрет и должен маскироваться.

## P3. Техдолг и инфраструктура

### IMP-18. Room schema export и миграции

- Факт: `exportSchema = false`, `version = 1`, миграций нет. Любое изменение
  схемы (IMP-01, IMP-09) без миграции сотрёт или сломает данные.
- Предложение: включить `exportSchema = true` + `room.schemaLocation`, коммитить
  JSON-схемы, писать `Migration`-тесты (`MigrationTestHelper`). Сделать это
  **до** IMP-01.

### IMP-19. Разделение больших классов

- `ProxyVpnService.kt` — 745 строк (TUN, watchdog, reconnect, уведомление,
  переключение маршрута). Предложение: вынести watchdog и reconnect-цикл в
  отдельные тестируемые классы (`UpstreamWatchdog`, `ReconnectLoop`) без
  изменения поведения.
- `VpnViewModel` — один ViewModel на все экраны. При росте функциональности
  (IMP-09, IMP-10) разделить на `ProxyListViewModel`/`AddEditViewModel`.

### IMP-20. Инструментальные и UI-тесты

- Сейчас 145 unit-тестов и только шаблонный `ExampleInstrumentedTest`.
- Предложение: Compose UI-тесты для Add/Edit (parse → ambiguous toggle → save
  blocked), списка (delete/undo), Home (start blocked без прокси). Запуск на
  эмуляторе в CI (Gradle Managed Devices) — оценить время/стоимость из-за
  тяжёлого libbox.

### IMP-21. Lint и статический анализ в CI

- В CI только `test` и `assembleDebug`. Добавить `./gradlew lint` (с baseline) и,
  опционально, detekt/ktlint без массового переформатирования существующего
  кода.

### IMP-22. Обновление libbox/sing-box

- Закреплён libbox 1.13.13. Предложение: документированная процедура
  обновления (новая сборка AAR, sha256 в `gradle/libbox.properties`, прогон
  `docs/qa/manual-vpn-checklist.md`), проверка CVE/релизов sing-box раз в
  релиз.

### IMP-23. Release notes и changelog

- Генерировать заметки релиза из коммитов (`gh release create --generate-notes`
  или `CHANGELOG.md`), чтобы на странице релиза было видно, что изменилось.
